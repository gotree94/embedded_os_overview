## 1. 메모리 보호: 문제 상황 재현

기본 FreeRTOS에서 흔한 사고:

```c
static char big_log[256];

void vLogTask(void *pv)
{
    for (;;) {
        char *p = get_next_msg();     // 실수로 NULL 반환
        sprintf(big_log, "%s", p);    // NULL 복사 → 하드폴트
    }
}
```

- 모든 태스크가 **같은 주소 공간(스택 제외)** 공유 → 포인터 오류가 시스템 전체로 확산
- 태스크 스택 오버플로도 이웃 태스크 데이터를 파괴

### 대응 단계

1. `configCHECK_FOR_STACK_OVERFLOW = 2` + 오버플로 훅
2. 큐/블록 기반 메시지로 raw 포인터 전달 금지
3. **FreeRTOS-MPU** 포트 사용 (Cortex-M33/M4 MPU 보유 칩)

## 2. FreeRTOS-MPU 개요

- 태스크별로 **MPU 영역**(코드, 스택, 데이터) 권한 부여
- `xTaskCreateRestricted()` / `xTaskCreateRestrictedStatic()`로 생성
- 스택 오버플로·미허가 접근 시 MPU 폴트 → 핸들러에서 해당 태스크 격리/재시작 가능
- Zephyr의 MPU 기반 보호와 개념적으로 유사 (→ `03_Zephyr`와 비교)

```c
TaskParameters_t params = {
    .pvTaskCode = vSensorTask,
    .pcName = "sensor",
    .usStackDepth = 256,
    .uxPriority = 2,
    .puxStackBuffer = sensor_stack,
    .xRegions = { /* MPU 영역 정의 */ }
};
xTaskCreateRestricted(&params, &handle);
```

## 3. 스택·힙 설계 실무 공식

| 항목 | 산정 방법 |
|---|---|
| 태스크 스택 | 함수 호출 깊이 + 최대 지역 변수 + FPU/ISR 임계 + 안전 여유(30%) |
| 측정 | `uxTaskGetStackHighWaterMark()`로 최소 잔여 확인 후 감축 반복 |
| 힙 | `xPortGetFreeHeapSize()` / `xPortGetMinimumEverFreeHeapSize()` |
| 정적 할당 선호 | 안전 인증·장기 안정화 제품에서는 `configSUPPORT_STATIC_ALLOCATION=1`로 동적 할당 피함 |

## 4. AWS IoT (FreeRTOS) 연동 개요

AWS가 FreeRTOS를 인수한 이유: **IoT 기기를 클라우드에 안전하게 연결하는 표준 런타임** 제공.

구성 요소:
- MQTT 브로커 연결 (`coreMQTT`)
- TLS 1.2/1.3 (`mbedtls` 또는 `wolfSSL`)
- OTA 업데이트 에이전트
- 디바이스 프로비저닝 (자격 증명)

개념적 흐름:
```
FreeRTOS 태스크 → MQTT Publish → TLS 세션 → AWS IoT Core → 규칙 → 다른 서비스
```

수업에서는 실제 클라우드 연동 대신 **MQTT 브로커(예: mosquitto) 로컬 서버 + mbedtls 미니 예제**로 대체 가능합니다.

## 5. FreeRTOS vs Zephyr vs Bare Metal 선택 재검토

| 상황 | 선택 |
|---|---|
| 단일 센서 + 전력 민감, 16KB Flash | Bare Metal 유지 |
| 태스크 2~5개, 칩 벤더 SDK 사용 | **FreeRTOS** |
| BLE/Matter/Thread 스택 필요 | **Zephyr** |
| 태스크별 강한 메모리 격리 + 통합 스택 | **Zephyr**(MPU) 또는 FreeRTOS-MPU |
