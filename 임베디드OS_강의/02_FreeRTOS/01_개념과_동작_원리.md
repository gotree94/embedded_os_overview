# FreeRTOS — 개념과 동작 원리

> 3일차 이론 (60분)

---

## 1. 개념

- 2003년 Richard Barry가 개발, **2017년 Amazon Web Services가 인수**.
- 전 세계에서 **가장 널리 배포된 오픈소스 MCU용 RTOS**.
- 애플리케이션을 여러 **독립 Task**로 분리하고, 작은 **선점형(Preemptive) 커널**이 관리.

```
애플리케이션
 ├─ Task A (센서, 우선순위 3)
 ├─ Task B (통신, 우선순위 2)
 └─ Task C (로깅, 우선순위 1)
        ↓
FreeRTOS 커널 (스케줄러, 큐, 타이머)   ← Flash 약 4~9KB
        ↓
하드웨어 (Cortex-M / ESP32 / RISC-V ...)
```

---

## 2. 동작 원리

- 스케줄러가 Task **우선순위**를 계속 감시하고 **Context Switching**을 수행
- 우선순위가 높은 Task는 필요한 순간 즉시 실행 (결정적 타이밍)
- 기본 동작: **선점형**. `vTaskDelay()` 등에 의해 자발적으로 양보하거나, 인터럽트에서 깨어난 높은 우선순위 태스크가 즉시 실행

### 스케줄 규칙 (핵심 3가지)

1. **항상 실행 준비된 태스크 중 가장 높은 우선순위 태스크가 실행**된다.
2. 동일 우선순위 태스크끼리는 **라운드로빈**(tick마다 전환)으로 시간을 나눈다.
3. 태스크가 `vTaskDelay()` / 큐 수신 대기 등으로 블록되면 그 자리를 낮은 우선순위 태스크가 채운다.

---

## 3. 주요 동기화·통신 수단

| 수단 | 용도 |
|---|---|
| **Queue** | 태스크 간 데이터 전송, ISR → 태스크 통신 (`xQueueSendFromISR`) |
| **Mutex** | 공유 자원 보호 (우선순위 상속 포함) |
| **Semaphore** | 신호, 자원 카운팅, ISR에서 태스크 깨우기 |
| **Event Group** | 여러 이벤트의 동시(AND) / 임의(OR) 대기 |
| **Task Notification** | 큐 없이 단방향 통신. 오버헤드 최소화 |
| **Software Timer** | 주기적 함수 호출 (타이머 서비스 태스크에서 실행) |
| **Stream/Message Buffer** | 바이트 스트림 / 가변 길이 메시지 전송 |

---

## 4. 장점

- 커널 크기 약 **4~9KB Flash**로 매우 작음
- ST, Espressif, NXP, Microchip 등 **주요 칩 벤더 SDK에 기본 통합** (CubeMX, ESP-IDF 등)
- 학습 자료·예제 풍부, 이식성 높음 (100+ 포트)
- AWS IoT 연동 생태계(coreMQTT, FreeRTOS+TLS) 존재

## 5. 단점

- 기본 설정에서는 모든 Task가 **하나의 보호되지 않는 메모리 공간**을 공유
  → 로깅 Task의 Null 포인터나 스택 오버플로가 전체 시스템을 다운시킬 수 있음
- 기본은 "실행기(Executor)"에 불과 → 네트워크, 파일시스템, 암호화 스택은 **서드파티 라이브러리로 별도 통합** 필요
- 스택 크기·큐 깊이 등 **자원 설계를 개발자가 직접** 책임져야 함

> 보완: MPU 기반 **FreeRTOS-MPU** 포트로 태스크별 메모리 보호가 가능합니다. AWS의 네트워크·보안 라이브러리도 FreeRTOS 생태계에 포함되어 있습니다.

---

## 6. 대표 적용 사례

ESP32 스마트홈 허브, 웨어러블 활동 추적기, 스마트 전력/수도 계량기, 산업용 센서 트랜스미터

## 7. 핵심 코드 구조

```c
void vSensorTask(void *pv)
{
    for (;;) {
        read_sensor();
        vTaskDelay(pdMS_TO_TICKS(10));
    }
}

int main(void)
{
    xTaskCreate(vSensorTask, "sensor", 256, NULL, 3, NULL);
    xTaskCreate(vLogTask,    "log",    256, NULL, 1, NULL);
    vTaskStartScheduler();   // 여기서부터 태스크가 경쟁
}
```

## 8. Bare Metal 대비 어디서 오는가

| 문제 (Bare Metal) | FreeRTOS 해법 |
|---|---|
| 루프 멈춤 → 전체 정지 | 각 작업이 독립 태스크, 블록해도 다른 태스크 진행 |
| 우선순위 없는 이벤트 처리 | 우선순위 기반 선점 스케줄링 |
| 동기화 코드 직접 작성 | Mutex/Semaphore/Queue 제공 |
| UART 2대 동시 수신 관리 복잡 | 태스크 분리 + 큐 |
