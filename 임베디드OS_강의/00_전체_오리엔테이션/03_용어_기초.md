# 용어 기초

이후 차시에서 반복 사용되는 용어를 하루에 정리합니다.

---

## 1. 실행 환경 관련

| 용어 | 정의 | 예시 |
|---|---|---|
| **Bare Metal** | OS 없이 하드웨어 레지스터를 직접 제어하는 방식 | 전동칫솔 펌웨어 |
| **Super Loop** | `while(1)` 안에서 모든 처리를 순차 실행하는 구조 | `read → update → drive` |
| **RTOS** | 실시간 요구사항을 만족하도록 태스크를 스케줄링하는 OS | FreeRTOS, Zephyr, VxWorks |
| **Task (태스크)** | RTOS가 스케줄링하는 독립 실행 단위 | 센서읽기 태스크, 로깅 태스크 |
| **선점형(Preemptive)** | 우선순위가 높은 태스크가 즉시 CPU를 빼앗아 실행하는 방식 | FreeRTOS 기본 |
| **협력형(Cooperative)** | 태스크가 스스로 양보할 때까지 실행하는 방식 | µITRON 일부, 수동 스케줄러 |
| **Context Switching** | 태스크 전환 시 레지스터·스택 상태를 저장/복원하는 것 | 태스크당 수 µs |
| **ISR (인터럽트 핸들러)** | 하드웨어 이벤트 발생 시 실행되는 짧은 함수 | EXTI0_IRQHandler |

## 2. 실시간성

| 용어 | 정의 |
|---|---|
| **Hard Real-Time** | 마감(deadline) 초과가 곧 시스템 실패인 경우. 예: 에어백 제어, 비행제어 |
| **Soft Real-Time** | 마감 초과 시 성능 저하이나 기능은 유지. 예: 스트리밍, HMI 갱신 |
| **결정적(Deterministic)** | 입력이 같으면 항상 같은 시간 내 응답함. RTOS의 핵심 가치 |
| **지터(Jitter)** | 응답 지연의 편차. 마이크로초급 지터가 필요한 분야: 철도 신호, 오디오 |

## 3. 커널 구조

| 용어 | 정의 |
|---|---|
| **모놀리식 커널** | 드라이버·파일시스템·네트워크 스택이 모두 커널 메모리 공간에서 동작. Linux, VxWorks |
| **마이크로커널** | 스케줄링·IPC만 커널에 두고 나머지는 User Space 프로세스로 격리. QNX |
| **커널 오버헤드** | OS가 사용하는 Flash/RAM/실행 시간. FreeRTOS 커널 약 4~9KB Flash |
| **IPC** | 프로세스/태스크 간 통신. 메시지, 큐, 공유 메모리 등 |

## 4. 메모리 보호

| 용어 | 정의 |
|---|---|
| **MPU** | Memory Protection Unit. MCU에 탑재된 보호 유닛. 영역별 읽기/쓰기/실행 권한 설정. Zephyr, FreeRTOS-MPU |
| **MMU** | Memory Management Unit. 가상 메모리 + 프로세스 격리. Cortex-A(Embedded Linux) |
| **결함 격리** | 일부 모듈의 실패가 전체 시스템으로 확산되지 않도록 하는 설계. QNX의 핵심 |

## 5. 임베디드 Linux 관련

| 용어 | 정의 |
|---|---|
| **AP (Application Processor)** | Cortex-A급 고성능 프로세서. Linux 탑재 대상 |
| **Buildroot** | 단순·빠른 빌드 시스템. 소규모 이미지에 적합 |
| **Yocto Project** | 레이어 기반 빌드 시스템. 대규모·장기 제품 관리에 적합 |
| **크로스 컴파일** | 호스트(x86)에서 타깃(ARM) 실행 파일을 빌드하는 것 |
| **루트 파일시스템** | `/` 부터 시작하는 전체 파일 트리. BusyBox가 흔히 사용됨 |
| **PREEMPT_RT** | Linux를 실시간화하는 메인라인 패치 |

## 6. 안전 인증

| 용어 | 적용 분야 |
|---|---|
| **DO-178C** | 상업용 항공전자 소프트웨어 |
| **IEC 61508** | 산업 자동화 전반의 기능안전 |
| **ISO 26262** | 자동차 기능안전 (ASIL A~D 등급) |
| **인증 산출물** | OS 벤더가 제공하는 검증 문서 패키지. **제품 인증은 별도 필요** |

## 7. IoT/커넥티비티

| 용어 | 정의 |
|---|---|
| **BLE** | Bluetooth Low Energy. 저전력 근거리 무선 |
| **Thread / Matter** | 스마트홈용 IPv6 메시 네트워크와 상호운용 표준. Zephyr에 내장 |
| **Device Tree** | 하드웨어 구성(핀맵, 주변장치)을 소스코드와 분리해 기술하는 포맷 |
| **Kconfig** | Zephyr/Linux에서 빌드 시 기능 옵션을 선택하는 설정 시스템 |

## 8. 확인 문제

1. Hard Real-Time과 Soft Real-Time의 차이를 제품 예시와 함께 설명하시오.
2. 모놀리식 커널과 마이크로커널의 메모리 공간 구성 차이를 그리시오.
3. MPU와 MMU는 각각 어느 하드웨어에 탑재되고, 어떤 문제를 해결하는가?
4. "OS 인증"과 "제품 인증"의 차이는?

### 답안 요지
1. 마감 초과가 시스템 실패인지(Hard: 에어백), 성능 저하인지(Soft: 스트리밍)의 차이
2. 모놀리식=커널 공간 일체 / 마이크로커널=커널(IPC·스케줄링) + User Space 프로세스
3. MPU=MCU(Cortex-M), 영역 권한; MMU=AP(Cortex-A), 가상 메모리·프로세스 격리
4. OS 인증은 런타임 플랫폼의 인증 산출물, 제품 인증은 최종 기기에 대한 별도 인증
