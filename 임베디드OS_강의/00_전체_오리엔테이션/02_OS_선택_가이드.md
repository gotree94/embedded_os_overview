# OS 선택 가이드

요구사항 → OS로 이어지는 의사결정 트리를 익히고, 실제 제품 사례에 적용해 봅니다.

---

## 1. 선택 의사결정 트리

```
Q1. 안전 인증(항공/자동차/의료)이 필수인가?
    ├─ 예 → 예산 있음 → VxWorks (항공·방산·의료·철도) / QNX (자동차)
    └─ 아니오 ↓
Q2. Cortex-A급 AP + 풍부한 SW 생태계(GUI, DB, 네트워크)가 필요한가?
    ├─ 예 → Embedded Linux (Buildroot / Yocto)
    └─ 아니오 ↓
Q3. 동시에 여러 작업을 처리해야 하는가?
    ├─ 아니오 (단순 제어) → Bare Metal
    └─ 예 ↓
Q4. BLE/Thread/Matter 등 통합 프로토콜 스택과 멀티 아키텍처 이식성이 중요한가?
    ├─ 예 → Zephyr
    └─ 아니오 → FreeRTOS
```

---

## 2. 요구사항별 우선 검토 OS

| 요구사항 | 1순위 | 2순위 | 설명 |
|---|---|---|---|
| 최소 비용/전력, 단순 제어 | Bare Metal | FreeRTOS | OS 오버헤드 자체가 없는 것이 이득 |
| 결정적 타이밍 + 널리 쓰이는 생태계 | FreeRTOS | Zephyr | 칩 벤더 SDK 기본 통합 |
| BLE/Matter/Thread 통합 스택 | Zephyr | FreeRTOS(+서드파티) | 프로토콜 스택이 플랫폼에 내장 |
| GUI·DB·웹·대용량 스토리지 | Embedded Linux | QNX | 소프트웨어 생태계가 결정적 |
| DO-178C / IEC 61508 인증 | VxWorks | QNX | 인증 산출물 패키지 |
| ISO 26262 ASIL D + 결함 격리 | QNX | VxWorks(ASIL D 경로) | 자동차 콕핏·ADAS 표준 |
| 마이크로초급 Hard RT + 결함 격리 | QNX | VxWorks | 마이크로커널 격리 |

## 3. 제품 사례별 선택 연습

| 제품 | 선택 OS | 핵심 이유 |
|---|---|---|
| (a) 전동칫솔 | **Bare Metal** | 단순 상태 머신, 비용·전력 민감, 인증 불필요 |
| (b) Nordic nRF53 Matter 스마트 조명 | **Zephyr** | Matter/Thread/BLE 스택 내장, nRF 공식 지원 |
| (c) 차량 디지털 콕핏 | **QNX** | ISO 26262 ASIL D, 드라이버 결함 격리 |
| (d) EV 충전기 터치 단말 | **Embedded Linux** | 터치 GUI, 네트워크 결제, DB, OTA |
| (e) 화성 탐사 로버 제어 | **VxWorks** | 임무 불가능(Hard RT), 방사선 환경 검증 이력 |
| (f) 산업용 무선 센서 노드 | **FreeRTOS** | 저비용 MCU, 센서+통신 동시 처리 |
| (g) TV 리모컨 | **Bare Metal** | 초저가, 단일 버튼 이벤트 처리 |

## 4. 비용·일정 관점 체크리스트

- [ ] 인증 비용 예산이 있는가? (VxWorks/QNX 라이선스 + 인증 컨설팅)
- [ ] 팀의 OS 숙련도는? (FreeRTOS 숙련 시 Zephyr/ Linux 전환 비용 발생)
- [ ] 칩 벤더 SDK의 OS 기본 지원 여부 (ST·Espressif·NXP·Microchip → FreeRTOS)
- [ ] 부팅 시간 요구 (ms급이면 Bare Metal/RTOS, 초 단위 OK면 Linux)
- [ ] RAM/Flash 예산 (RTOS: KB급 / Linux: MB~GB급)
- [ ] 장기 유지보수·OTA 체계 (Linux/Zephyr 생태계 유리)
