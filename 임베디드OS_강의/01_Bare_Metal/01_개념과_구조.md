# Bare Metal (OS 없음) — 개념과 구조

> 2일차 이론 (50분)

---

## 1. 개념

- OS, 스케줄러 등 모든 추상화 계층을 제거하고 **하드웨어 레지스터를 직접 제어**하는 방식.
- 전체 코드가 하나의 `while(1)` **Super Loop** 안에서 동작하며, 외부 이벤트는 **하드웨어 인터럽트**로 처리.
- 1970년대 초기 마이크로컨트롤러와 함께 등장한 가장 오래된 방식.

```
애플리케이션 (상태 머신, 연산)
      ↓ 레지스터 직접 접근
하드웨어 (GPIO, UART, Timer, ADC)
```

---

## 2. 동작 구조

```
main()
 ├─ hw_init()        // 클럭, GPIO, 주변장치 초기화
 └─ while(1)         // Super Loop
     ├─ read_sensors()           // 논블로킹으로 센서 읽기
     ├─ update_state_machine()   // 상태 머신 갱신
     └─ drive_outputs()          // 출력 갱신

ISR (예: EXTI0)
 └─ 짧게 이벤트 플래그만 세팅
```

**핵심 원칙**: ISR에서는 가능한 짧게, 메인 루프에서 실제 처리.

---

## 3. 장점

- 커널·스케줄러가 없어 **오버헤드 0**, ROM/Flash 100%를 애플리케이션에 사용
- 전원 인가 즉시 실행, **최소 전력**, 마이크로초 단위 응답 지연
- 타이밍이 코드 흐름 그 자체 → 예측이 직관적

## 4. 단점

- 복잡한 다단계 상태 머신을 하나의 루프에 넣으면 코드가 비대해지고 유지보수가 어려움
- 느린 센서 읽기나 외부 버스 응답을 기다리며 한 함수가 멈추면 **시스템 전체가 정지**
  → 모든 주변장치를 **Non-blocking** 방식으로 작성해야 함
- 파일시스템, 네트워크 드라이버, **메모리 보호 기능 없음** → 저수준 드라이버를 직접 작성/이식

---

## 5. 대표 적용 사례

전동칫솔, TV 리모컨, 전동공구 안전 인터락, 저가 센서 노드, 저전력 차량 제어 모듈

---

## 6. RTOS 없이 버티는 한계와 요즘의 중간 해법

- 요즘은 RTOS 없이도 **인터럽트 + 상태 머신 + 협력형 스케줄러(cooperative scheduler)**로 상당한 복잡도를 감당하기도 합니다.
- 협력형 스케줄러: 루프가 빠르게 순회하며, 각 함수가 스스로 시간 초과 시 양보하는 방식.
- 다만 **우선순위 선점**이 필요해지는 순간(예: 긴급 정지 신호가 데이터 수집보다 우선) FreeRTOS 전환을 고민해야 합니다.

---

## 7. 핵심 코드 구조

```c
int main(void)
{
    hw_init();
    while (1) {            // Super Loop
        read_sensors();
        update_state_machine();
        drive_outputs();
    }
}

void EXTI0_IRQHandler(void)   // 하드웨어 인터럽트
{
    // 이벤트 처리 (짧게!)
}
```
