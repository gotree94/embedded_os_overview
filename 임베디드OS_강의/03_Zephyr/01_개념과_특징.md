# Zephyr RTOS — 개념과 특징

> 5일차 이론 (50분)

---

## 1. 개념

- 단순 Task 라이브러리가 아닌 **현대적 소프트웨어 플랫폼**에 가까운 RTOS.
- **2016년 Linux Foundation** 산하에서 출범. Nordic Semiconductor, NXP, Intel, Meta, Google, AWS, Microsoft, Qualcomm 등이 후원.
- 자원이 제한된 IoT 개발에 **통일된 구조와 표준화**를 제공.

```
애플리케이션 (C/C++)
 ├─ Kconfig로 선택된 서브시스템 (BLE, 네트워크, 셸, USB, 파일시스템...)
 ├─ HAL / 드라이버 (Device Tree로 바인딩)
 └─ Zephyr 커널 (선점형, MPU 지원)
```

---

## 2. Linux에서 영감받은 설계

| 구성 | 역할 |
|---|---|
| **Device Tree** (DTS/overlay) | 하드웨어(핀맵, 주변장치, 클럭)를 **C 코드와 분리**해 기술. 소스 변경 없이 보드 교체 가능 |
| **Kconfig** | 빌드 시점에 기능 옵션 선택 (`CONFIG_BT=y` 등). `.config` 파일로 관리 |
| **CMake 빌드** | 커널·앱·드라이버를 통합 빌드 |
| **West** | 다중 저장소(manifest) 관리 도구 + 빌드/플래시 인터페이스 |

FreeRTOS가 애플리케이션 단에서 태스크를 만드는 방식이라면, Zephyr는 **보드+기능 구성 자체를 선언적**으로 정의합니다.

---

## 3. 즉시 사용 가능한 프로덕션급 프로토콜 스택

- **Bluetooth Low Energy** (Central/Peripheral/Beacon)
- **Wi-Fi** (주요 SoC 지원)
- **IEEE 802.15.4 / Thread / Zigbee**
- **Matter** (스마트홈 상호운용 표준 — nRF53, ESP32 등에서 인증 취득에 활용)
- **CAN, USB, TCP/IP (bsd_socket/LwIP), MQTT, CoAP, HTTP, DNS, DHCP**

→ FreeRTOS 사용 시 이런 스택을 각각 서드파티로 조립해야 하는 것과 대비.

---

## 4. 이식성

- 같은 애플리케이션 코드를 **ARM Cortex-M, RISC-V, ESP32, x86, Nios V, ARC** 등에 재컴파일
- 보드 선택만 바꾸면 빌드됨:
  ```
  west build -b nrf52840dk/nrf52840 samples/hello_world
  west build -b qemu_cortex_m3 samples/hello_world   # 보드 없이 시뮬레이션
  ```

---

## 5. 메모리 보호

- **MPU(Memory Protection Unit)** 기반 하드웨어 수준 메모리 보호
- 스레드(태스크)·아이솔레이션(격리 영역)·메모리 도메인(2.4+) 등 다층 보호
- 커널 모듈과 애플리케이션 영역 분리, 스택 오버플로 시 보호 폴트 발생

---

## 6. 장점 요약 vs FreeRTOS

| 항목 | FreeRTOS | Zephyr |
|---|---|---|
| 범위 | 커널 | 커널 + 프로토콜 스택 + 드라이버 모델 + 도구 |
| 하드웨어 기술 | 코드에 직접 기술 | Device Tree로 분리 |
| 빌드 구성 | FreeRTOSConfig.h | Kconfig + CMake |
| 프로토콜 | 서드파티 조립 | 내장 (BLE/Matter/Thread 등) |
| 보호 | 기본 없음(선택적 MPU 포트) | MPU 기반 보호 내장 |

---

## 7. 단점

- CMake + Device Tree + Kconfig 설정으로 **FreeRTOS 대비 학습 곡선이 가파름**
- Flash 사용량이 큼: 기본 구성만도 **20~50KB 이상** (실제 앱은 이보다 큼)
- 드라이버 지원 범위는 칩·모듈에 따라 달라 확인 필요

---

## 8. 대표 적용 사례

BLE 자산 추적기, 스마트 헬스 모니터, **Nordic nRF52/nRF53** 기반 Matter 인증 스마트홈 기기

---

## 9. 프로젝트 구조 예시

```
app/
├── CMakeLists.txt       # 프로젝트/앱 정의
├── prj.conf             # Kconfig 옵션 (필요한 기능만 켠다)
├── boards/
│   └── my_board.overlay  # Device Tree overlay (보드별 핀 배정)
└── src/
    └── main.c
```

`prj.conf` 예시:
```
CONFIG_GPIO=y
CONFIG_SERIAL=y
CONFIG_BT=y
CONFIG_BT_PERIPHERAL=y
CONFIG_HEAP_MEM_POOL_SIZE=8192
```
