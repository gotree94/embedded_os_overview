# QNX Neutrino — 개념과 마이크로커널

> 8일차 이론 (60분)

---

## 1. 개념

- 1980년 **Quantum Software Systems** 개발, **2010년 BlackBerry 인수**.
- 진정한 **마이크로커널(Microkernel)** 구조의 상용 RTOS.
- 모놀리식 OS(VxWorks, Linux)는 드라이버·파일시스템·네트워크 스택이 **하나의 커널 메모리 공간**에서 돌지만, QNX는 마이크로커널에 **스케줄링과 프로세스 간 통신(IPC)** 같은 필수 기능만 두고 **나머지는 격리된 User Space 프로세스**로 실행.

```
[ User Space ]
  드라이버 프로세스 | 파일시스템 | 네트워크 스택 | 미디어 앱 ...
        ↕ 메시지 전달 (IPC)
[ Kernel Space: 마이크로커널 ]
  스케줄링 · 인터럽트 · IPC · 타이머
```

---

## 2. 장점

- **탁월한 결함 격리**: 3D 그래픽 드라이버나 미디어 플레이어가 죽어도 마이크로커널이 **해당 프로세스만 수 ms 내 재시작**, 핵심 안전 기능은 영향 없음
- Hard Real-Time 성능 + 최고 수준의 **ISO 26262 (ASIL D)** 기능안전 인증
- POSIX 호환 API → Linux 경험 이전 쉬움
- 다중 SoC/아키텍처 지원, SMP, 가상화(QNX Hypervisor) — 디지털 콕핏에서 인스트루먼트·인포테인먼트 분리 격리

## 3. 단점

- 높은 상용 라이선스 비용 → 엔터프라이즈 예산 한정
- 마이크로커널 IPC로 인해 모놀리식 커널 대비 **Context Switching 오버헤드 소폭 증가**

---

## 4. 모놀리식 vs 마이크로커널

| 구분 | 모놀리식 (VxWorks, Linux) | 마이크로커널 (QNX) |
|---|---|---|
| 드라이버/FS/네트워크 | 커널 공간 | **User Space 프로세스** |
| 장애 영향 | 커널 전체로 확산 가능 | **해당 프로세스만 재시작** |
| 성능 | IPC 오버헤드 적음 | IPC 오버헤드 소폭 증가 |
| 인증 복잡도 | 커널 전체 검증 | 마이크로커널만 집중 검증 + 분리 인증 가능 |

---

## 5. 왜 자동차인가

- 디지털 콕핏: 계기판(안전) + 인포테인먼트(복잡·불안정)를 **같은 SoC에서 격리 실행**
- **ADAS**: 카메라·레이더 처리 파이프라인의 결함이 제어 루프로 전이 방지
- **ASIL D** 인증 요구와 결합: 가장 높은 자동차 안전 등급 충족
- **2억 3천만 대 이상**의 차량에 탑재 (누적)

---

## 6. QNX의 기술 요소

| 요소 | 설명 |
|---|---|
| 메시지 파싱(Message Passing) | 태스크/프로세스 간 동기·비동기 통신의 핵심 |
| 리소스 매니저 | 드라이버가 User Space에서 커널 인터페이스로 장치 서비스 제공 |
| 심볼릭 링크 | POSIX `devc-*`, `devb-*` 등 디바이스 매니저 |
| QNX Hypervisor | 가상 머신으로 OS 격리 (Linux/Android 병행) |
| Adaptive Platform | AUTOSAR Adaptive + QNX 조합의 SDV(소프트웨어 정의 차량) 아키텍처 |

---

## 7. FreeRTOS/VxWorks와 비교해 위치 잡기

| 상황 | 선택 후보 |
|---|---|
| IoT 센서, 비용 민감 | FreeRTOS |
| 항공/우주, 철도, 의료(장비) | VxWorks |
| 자동차 콕핏·ADAS, 복합 OS 동거 | **QNX** |
| 열린 생태계·표준 스택·저비용 | Zephyr |
