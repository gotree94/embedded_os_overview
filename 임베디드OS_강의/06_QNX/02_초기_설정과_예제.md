# QNX — 초기 설정과 예제

> 8일차 실습 (120분) · QNX Software Development Platform (SDP) + QEMU x86_64

> QNX는 상용 라이선스가 필요합니다. 교육용으로는 **BlackBerry/QNX의 평가용 SDP**(qnx.com에서 신청) 또는 강사 준비 환경을 사용합니다.
> 공개 문서: https://www.qnx.com/developers/docs/

---

## 1. 사전 준비

| 항목 | 내용 |
|---|---|
| 계정 | qnx.com 평가용 SDP 다운로드 권한 (교육 기관 신청 포함) |
| 호스트 | Linux x86_64(권장) 또는 Windows. RAM 16GB+ |
| 가상화 | QEMU (SDP에 포함 또는 별도 설치) |
| 보드 | 없음 (QEMU로 실습 가능). 실물 x86/ARM 보드는 별도 BSP |

---

## 2. SDP 설치 (Linux 기준)

1. 평가용 SDP tarball/설치 파일을 다운로드
2. 설치 스크립트 실행 (예시):
   ```bash
   ./qnx-sdp-<version>-installer.run
   # 설치 경로: ~/qnx71 또는 지정 경로
   ```
3. 환경 설정:
   ```bash
   source ~/qnx71/qnx650-env.sh
   qcc -V          # 컴파일러 확인
   mkifs --version # 이미지 빌드 도구 확인
   ```

주요 도구:
| 도구 | 역할 |
|---|---|
| `qcc` / `QCC` | C/C++ 컴파일러 |
| `mkifs` | Initial Filesystem 이미지 빌드 |
| `lsifs`, `dumpifs` | 이미지 분석 |
| `procnto*` | 마이크로커널 프로세스명 |
| `devc-*` | 문자 디바이스 매니저 |
| `devb-*` | 블록 디바이스 매니저 |

## 3. QEMU에서 부팅

SDP에 포함된 x86 이미지 부팅 예시:
```bash
qemu-system-x86_64 -m 1G -nographic \
  -drive file=ifs-x86_64,if=ide,format=raw \
  -serial mon:stdio
```

또는 평가 패키지의 스크립트:
```bash
./launch-qemu.sh
```

부팅 후 셸:
```
/ #            ← pps / sh 셸
/ # pidin ar   /* 실행 중인 프로세스 열거 — 마이크로커널 + 매니저들 */
```

`pidin ar` 출력 예시:
```
PID NAME              ARGUMENT
  1 procnto-smp       ...
  3 devc-con           ...
  5 slogger2           ...
  8 devb-umass          ...
```

## 4. 예제 1. 'Hello' 메시지 서버/클라이언트 (40분)

QNX의 핵심은 **메시지 파싱**입니다. 간단한 서버(스レ드)와 클라이언트 예시:

**server.c** (요약)
```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/neutrino.h>

#define MY_ID 0x123

int main(void)
{
    int rcvid;
    struct { long mtype; char msg[32]; } rx, tx;

    int chid = ChannelCreate(0);
    printf("server: chid=%d\n", chid);

    for (;;) {
        rcvid = MsgReceive(chid, &rx, sizeof(rx), NULL);
        if (rcvid == -1) continue;

        snprintf(tx.msg, sizeof(tx.msg), "hello, client!");
        tx.mtype = 1;
        MsgReply(rcvid, EOK, &tx, sizeof(tx));
    }
}
```

**client.c** (요약)
```c
#include <stdio.h>
#include <sys/neutrino.h>
#include <sys/dispatch.h>

int main(int argc, char **argv)
{
    int coid = ConnectAttach(0, atoi(argv[1]), 0, _NTO_CO_SIDEKICK, 0);
    struct { long mtype; char msg[32]; } tx, rx;
    int rlen;

    tx.mtype = 1;
    strcpy(tx.msg, "ping");
    MsgSend(coid, &tx, sizeof(tx), &rx, sizeof(rx));
    printf("client: reply=%s\n", rx.msg);
    ConnectDetach(coid);
    return 0;
}
```

빌드·실행:
```bash
qcc -o server server.c
qcc -o client client.c
mkifs server client -I ifs.img      # 간이 이미지에 포함 (또는 PWD에서 직접 실행)
# 셸에서
./server &        /* PID 기록 */
./client <PID>
```

## 5. 예제 2. 드라이버 프로세스 재시작 관찰 (40분)

1. 셸에서 아무 문자 드라이버/자원 프로세스를 `slay`로 종료:
   ```
   slay slogger2
   ```
2. 시스템의 나머지(네트워크, 제어 루프)가 **유지**되는 것 확인 — 마이크로커널 결함 격리 체감.
3. 실무: 디스플레이 드라이버가 죽으면 IPC 연결이 끊긴 프로세스만 재시작되어 계기판(안전)이 정지하지 않음.

## 6. 예제 3. 자동차 콕핏 아키텍처 설계 실습 (이론)

QNX Hypervisor 기반 개념도 작성:
```
[ Hypervisor ]
 ├─ VM1: QNX (계기판, ASIL D, 마이크로초 제어)
 ├─ VM2: QNX 또는 Linux (ADAS HMI)
 └─ VM3: Linux/Android (인포테인먼트, 앱 생태계)
```

1. 각 기능의 ASIL 등급 후보

3. 장애 시나리오(미디어 앱 크래시) 대응 흐름을 그리기
