## 답안

1. 기본 스케줄러(CFS)가 **평균 지연 최소화**를 목표로 비결정적으로 동작하기 때문. → `PREEMPT_RT` 패치(또는 이를 포함한 커널)로 개선. 여전히 초단위 확률 지연이 필요하면 MCU + RTOS 병행.

2. **Buildroot**는 전체 시스템을 하나의 Defconfig로 통째로 빌드해 단순·빠름 → 소규모/학습. **Yocto**는 레이어·Recipe로 패키지 단위를 관리해 다수 보드·장기 유지보수에 유리하지만 복잡하고 빌드가 오래 걸림.

3. 데스크톱 배포판은 범용 하드웨어·패키지 저장소를 전제로 함. Embedded Linux는 **타깃 보드에 맞는 최소 커널과 최소 rootfs를 직접 구성**(드라이버, 라이브러리, 서비스만 포함)해 Flash/RAM·부팅 시간을 최적화.

4. **부트로더**(U-Boot): 커널 로드·이미지 관리·복구 모드. **커널**: 하드웨어 추상화·스케줄링·드라이버. **루트 FS**: 사용자 공간 프로그램·설정·라이브러리. **초기화 시스템**(systemd 등): 프로세스 시작 순서·의존성 관리·재시작.

5. 호스트(x86)와 타깃(ARM)의 명령어 집합이 달라 타깃용 실행 파일을 호스트에서 빌드해야 함. `-static`: 타깃 라이브러리 의존 없이 실행 가능(장점), 바이너리가 크고 보안 패치 반영이 어려움(단점).

6. 무인·원격 기동 장비에서 프로세스 크래시가 곧 제품 다운이므로, **자동 재시작으로 가용성을 확보**하기 때문. 로그(`journalctl`)로 사후 분석도 가능.

7. (b) — sysfs 인터페이스는 커널에서 단계적으로 제거되는 경향이며, libgpiod는 라인 단위 소유권·이벤트·동시 접근에 안정적.

8. **제어 루프**(ms 이하, 결정적)는 MCU + RTOS가 담당하고, **UI·네트워크·DB**(소프트 실시간, 풍부한 생태계)는 Linux가 담당하는 하이브리드 구조로 비용·성능·안정성을 동시에 만족.
