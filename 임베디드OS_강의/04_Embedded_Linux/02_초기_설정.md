# Embedded Linux — 초기 설정

> 6일차 실습 준비 (90분) · Buildroot 경로 (QEMU 또는 Raspberry Pi)

> 실무에서는 Yocto도 널리 쓰이지만, **학습·검증 속도** 때문에 Buildroot를 먼저 다룹니다.
> Yocto 개요는 §4 참고.

---

## 1. 호스트 환경 준비 (Ubuntu 22.04/24.04 또는 WSL2)

```bash
sudo apt update && sudo apt install -y \
  git build-essential bc bison flex libssl-dev libncurses-dev \
  u-boot-tools python3 python3-pyelftools meson ninja-build \
  qemu-system-arm debootstrap
```

> Buildroot 공식 권장 호스트 패키지 목록과 대체로 동일합니다.

---

## 2. Buildroot 받기 및 첫 빌드 (QEMU virt / vexpress)

```bash
git clone https://github.com/buildroot/buildroot.git
cd buildroot
make qemu_arm_vexpress_defconfig    # 32비트 ARM QEMU용
make -j$(nproc)                     # 첫 빌드: 수십 분 (캐시 생성 후 빨라짐)
```

결과물:
```
output/images/
├── zImage            # 커널
├── vexpress-v2p-ca9.dtb
└── rootfs.ext4       # 루트 파일시스템
```

---

## 3. QEMU에서 부팅 확인

```bash
make qemu-arm-run   # 또는 직접:
qemu-system-arm -M vexpress-a9 -m 256 \
  -kernel output/images/zImage \
  -dtb output/images/vexpress-v2p-ca9.dtb \
  -drive file=output/images/rootfs.ext4,if=sd,format=raw \
  -append "console=ttyAMA0,115200 root=/dev/mmcblk0 rw" \
  -nographic -net nic,model=lan9118 -net user
```

기대 결과:
```
Welcome to Buildroot
buildroot login: root   # 기본은 자동 로그인
# uname -a
Linux buildroot 6.x.x ...
```

`ls /`, `ps`, `top`, `dmesg | tail` 로 시스템 확인.

---

## 4. Yocto 경로 개요 (실무용)

```bash
mkdir ~/yocto && cd ~/yocto
git clone -b kirkstone git://git.yoctoproject.org/poky
source poky/oe-init-build-env build
```

`conf/local.conf`에 타깃 지정:
```
MACHINE = "raspberrypi4-64"
DISTRO_FEATURES_append = " systemd"
```

```bash
bitbake core-image-minimal     # 시간이 오래 걸림
```

| 용어 | 의미 |
|---|---|
| Layer | 기능 계층 (meta-raspberrypi 등) |
| Recipe (.bb) | 패키지 빌드 규칙 |
| Image | 최종 rootfs 구성 (core-image-minimal 등) |
| Machine | 타깃 보드 정의 |

---

## 5. 실제 보드: Raspberry Pi 이미지 (Buildroot)

```bash
make raspberrypi4_defconfig
make menuconfig   # (선택) 파일시스템 포맷, 부트로더 옵션
make -j$(nproc)
```

`output/images/sdcard.img`를 SD카드에 기록 (Win32DiskImager, `dd`, Raspberry Pi Imager의 raw 기능):
```bash
# 리눅스 (드라이버 주의!)
sudo dd if=output/images/sdcard.img of=/dev/sdX bs=4M status=progress conv=fsync
```

보드 전원 인가 → 시리얼 콘솔(115200) 또는 HDMI로 로그인.

---

## 6. 크로스 컴파일 툴체인 확인

Buildroot는 `output/host/bin/`에 호스트-타깃 툴체인을 만듭니다:

```bash
./output/host/bin/arm-linux-gnueabihf-gcc --version
```

간단한 앱 크로스 빌드:
```bash
./output/host/bin/arm-linux-gnueabihf-gcc -static hello.c -o hello
# rootfs에 복사 후 보드에서 실행
```

## 7. 자주 막히는 지점

| 증상 | 대처 |
|---|---|
| 패키지 다운로드 실패 | 방화벽/미러 문제. `make source`로 사전 다운로드 |
| `bison/flex` 에러 | 호스트 패키지 미설치 |
| QEMU 부팅 무한 대기 | `-nographic` + 올바른 `-append` 콘솔/tty 확인 |
| SD카드 부팅 불가 | 이미지 기록 후 파티션 캐시 플러시, 전원 5V/3A 확인 |
