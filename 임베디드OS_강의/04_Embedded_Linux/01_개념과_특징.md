# Embedded Linux — 개념과 특징

> 6일차 이론 (50분)

---

## 1. 개념

- MCU의 연산 여력이 한계에 달하면 **애플리케이션 프로세서(AP)**로 이동 → Embedded Linux 영역.
- 1991년 Linus Torvalds의 Linux 커널에서 출발.
- **데스크톱 배포판(Ubuntu 등)을 그냥 설치하는 것이 아님.**
  **Buildroot**나 **Yocto Project**로 우리 하드웨어에 맞춘 **최소 커널 + 루트 파일시스템**을 직접 빌드.

```
[애플리케이션: Qt/앱, DB, 웹 서버]
        ↓ 시스템 콜
[라이브러리: glibc/musl, BusyBox]
        ↓
[Linux 커널: 스케줄링, MMU, 드라이버, 네트워크 스택]
        ↓
[ARM Cortex-A AP, 수 MB~GB RAM, eMMC/SD]
```

---

## 2. MCU(MMU 없음)와 AP(MMU 있음)의 전환

| 항목 | MCU (Cortex-M) | AP (Cortex-A) |
|---|---|---|
| 메모리 보호 | MPU (영역 기반) | **MMU** (가상 메모리, 프로세스 격리) |
| 실행 환경 | RTOS 또는 Bare Metal | Linux |
| RAM | KB~수백 KB | 수 MB~GB |
| 부팅 | ms 단위 | **초 단위** |
| 생태계 | 칩 벤더 SDK | Python/C++/Rust, DB, Qt 등 |

---

## 3. 장점

- 거대한 소프트웨어 생태계: **Python, C++, Rust**, 관계형 DB, 웹 API, **Qt/TouchGFX** 등 그래픽 프레임버퍼
- USB, 터치 디스플레이, 플래시 스토리지, 고속 네트워크용 **검증된 드라이버**가 풍부
- 프로세스 격리(MMU), 표준 네트워킹, 패치·보안 업데이트 체계
- 크로스 개발 툴체인·디버거(GDB, JTAG, strace) 성숙

## 4. 단점

- 기본 스케줄링은 **Soft Real-Time / 비결정적** (`PREEMPT_RT` 패치로 개선 가능)
- **ARM Cortex-A급** 32/64비트 프로세서, 수 MB~GB 단위 RAM 필요
- 부팅 시간이 **밀리초가 아닌 초 단위** (최적화 시 수백 ms~1초대까지 단축 가능)
- 보안 업데이트·라이선스(SOSS) 관리 등 제품화 부담

---

## 5. 빌드 도구 비교

| 도구 | 특징 | 적합 |
|---|---|---|
| **Buildroot** | 단순하고 빠름, Make 기반, 전체 이미지를 통째로 빌드 | 소규모 이미지, 학습, 빠른 반복 |
| **Yocto Project** | 레이어(Layer) 기반, BitBake, 패키지 단위 관리 | 대규모·장기 제품, 다수 보드 지원 |

| 항목 | Buildroot | Yocto |
|---|---|---|
| 학습 곡선 | 낮음 | 높음 |
| 빌드 시간 | 짧음 (수십 분) | 길음 (수 시간~) |
| 패키징 단위 | 전체 파일시스템 | deb/rpm/ipk 패키지 |
| 커스텀 | Defconfig 중심 | 레이어·Recipe 중심 |
| 장기 유지보수 | 제한적 | 유리 |

---

## 6. 대표 적용 사례

스마트 TV UI, EV 충전기 단말, 차량 인포테인먼트 터치스크린, 네트워크 라우터, 산업용 게이트웨이 HMI

---

## 7. 구성 요소 지도

```
부트로더 (U-Boot)
   → 커널 (zImage/Image + Device Tree Blob)
      → 루트 파일시스템 (BusyBox / Buildroot rootfs / Yocto image)
         → 초기화 시스템 (systemd / BusyBox init / OpenRC)
            → 애플리케이션 서비스
```

---

## 8. 실시간성 보충

- 기본 커널(CFS 스케줄러)은 평균 지연 최소화가 목표 → **비결정적**
- `PREEMPT_RT`: 스파인 임계구간 비활성화, RT 뮤텍스 도입 등으로 **Hard Real-Time에 근접**. 메인라인 통합 흐름이 있으므로 최신 커널 버전 기준으로 확인
- 여전히 마이크로초 확률 지연은 RTOS 영역. 혼합 구조: **Linux(CPU-A) + MCU RTOS(제어 루프)**
